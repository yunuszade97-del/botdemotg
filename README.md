# Telegram-бот для лидогенерации с LLM

MVP-каркас бота, который консультирует клиента, квалифицирует его в диалоге
и через function calling отдаёт готовый лид владельцу бизнеса в Telegram.
Заточен под услуги и аренду: авто, недвижимость, туры, трансферы.

Стек: Python 3.11+ · aiogram 3 · FastAPI · OpenAI-совместимый LLM API ·
SQLite (aiosqlite) · pydantic-settings.

---

## Быстрый старт (5 минут)

```bash
git clone <repo> && cd botdemotg
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# заполните BOT_TOKEN, ADMIN_CHAT_IDS, LLM_API_KEY

python -m app.preflight   # можно ли запускать?
python -m app.main
```

`preflight` — это то, что стоит запускать перед каждым деплоем. Он проверяет
конфиг, запись в БД, токен, **достижимость админ-чатов** и **поддержку моделью
tool calling**, и возвращает код 1, если запускать нельзя:

```
[  OK  ] Конфигурация          режим polling, админов: 1
[  OK  ] База данных           data/bot.sqlite3
[  OK  ] База знаний           content/knowledge.md, 1993 символов
[  OK  ] Telegram: токен       @your_bot (id=123456789)
[ FAIL ] Telegram: админ-чаты  недоступны: [777]. Откройте бота с этих
                               аккаунтов и нажмите /start
[  OK  ] LLM: доступ           gpt-4o-mini отвечает
[  OK  ] LLM: tool calling     инструмент вызван (имя: Иван)
```

Бот поднимется в режиме long polling, HTTP-сервер — на `http://localhost:8080`
(`/healthz` для проверок живости).

Что нужно получить заранее:

| Значение          | Где взять                                                       |
|-------------------|-----------------------------------------------------------------|
| `BOT_TOKEN`       | [@BotFather](https://t.me/BotFather) → `/newbot`                 |
| `ADMIN_CHAT_IDS`  | [@userinfobot](https://t.me/userinfobot) → ваш `id`              |
| `LLM_API_KEY`     | [OpenAI](https://platform.openai.com/api-keys) или [OpenRouter](https://openrouter.ai/keys) |

> Важно: перед первым лидом напишите боту `/start` со своего админ-аккаунта.
> Telegram не даёт боту писать первым тому, кто с ним не общался.

## Как переключить бота на нового клиента

Код трогать не нужно — только два места.

**1. `content/knowledge.md`** — прайс, наличие, условия, FAQ. Файл целиком
подставляется в системный промпт. Пишите обычным текстом: чем конкретнее
цифры и условия, тем меньше модель фантазирует.

**2. Переменные в `.env`:**

```dotenv
COMPANY_NAME=Название компании
COMPANY_BUSINESS=аренда квартир посуточно
COMPANY_CITY=Тбилиси
WORKING_HOURS=ежедневно 10:00–20:00
MANAGER_RESPONSE_TIME=10 минут
WELCOME_MESSAGE=            # пусто — сгенерируется из полей выше
```

Сам тон и логика продаж живут в `app/core/prompts.py` — правьте, только если
нужно поменять стиль общения, а не факты о бизнесе.

## Как это работает

```
Telegram
   │  (polling | webhook)
   ▼
FastAPI ──► aiogram Dispatcher ──► middlewares (логи, троттлинг)
                                        │
                                        ▼
                              ConversationService
                       ┌────────────────┼────────────────┐
                       ▼                ▼                ▼
                  история из      LLM + tools        save_qualified_lead
                    SQLite      (2 прохода)                 │
                                                   ┌────────┴────────┐
                                                   ▼                 ▼
                                              лид в SQLite    уведомление
                                                                 админу
```

**Флоу диалога.** Каждое сообщение уходит в LLM вместе с системным промптом и
окном последних `HISTORY_LIMIT` реплик. Модель отвечает как менеджер по
продажам: коротко, по одному вопросу за раз, и собирает недостающие поля заявки.

**Квалификация.** Модели доступны два инструмента.

`request_phone_button` — показать кнопку «Отправить мой номер». Модель сама
решает, когда в разговоре пора брать контакт. Номер приходит подтверждённым
самим Telegram: это надёжнее, чем номер, который модель вычитала из текста.

`save_qualified_lead` — сохранить заявку. Вызывается, как только известны имя,
контакт, сроки и суть запроса:

| Поле               | Тип             | Описание                                  |
|--------------------|-----------------|-------------------------------------------|
| `client_name`      | `str`           | имя клиента                               |
| `phone_or_contact` | `str`           | телефон, @username, t.me-ссылка или e-mail |
| `dates_or_timing`  | `str`           | когда нужна услуга                        |
| `service_details`  | `str`           | что именно нужно + пожелания              |
| `budget`           | `str \| None`   | бюджет, если обсуждался                   |
| `summary`          | `str`           | выжимка диалога в 1–2 предложения         |

**Уведомление.** Лид пишется в SQLite, затем уходит в чаты из `ADMIN_CHAT_IDS`:

```
🔥 НОВЫЙ ГОРЯЧИЙ ЛИД!

👤 Имя: Иван
📞 Контакт: +7 999 123-45-67
📅 Сроки/Даты: 12–19 августа
🚗 Запрос: Toyota RAV4, нужен автомат
💰 Бюджет: до 100 GEL в сутки
📝 Суть: Клиент ищет кроссовер на неделю в августе.
💬 Профиль: @ivan · открыть чат

Заявка #7 · 2026-09-03 12:00:00
```

Клиенту модель отвечает подтверждением («данные зафиксировал, менеджер
свяжется в течение 5 минут»).

## Решения, которые стоит знать до правок

Это не абстрактные best practices — каждый пункт закрывает конкретный способ
уронить продакшен или потерять деньги.

**Два прохода к LLM на один вызов инструмента.** После `save_qualified_lead`
результат возвращается модели tool-сообщением, и она генерирует подтверждение.
Один проход оставил бы клиента без ответа. Лимит — `LLM_MAX_TOOL_ROUNDS`;
на исчерпании отдаётся шаблонное подтверждение, а не тишина.

**Раунды с инструментами не попадают в историю.** В БД пишутся только
текстовые ходы. Сохранённое `assistant`-сообщение с `tool_calls` без парного
`tool`-ответа роняет следующий запрос к API в 400.

**Дедупликация лидов.** Модель охотно перевызывает инструмент на каждом
следующем сообщении. Повтор с тем же контактом в пределах
`LEAD_DEDUP_WINDOW_MINUTES` не создаёт новую заявку и не будит админа второй раз.

**Валидация аргументов инструмента.** Аргументы приходят из генерации модели —
это такой же недоверенный ввод, как и пользовательский. `phone_or_contact`
проверяется на реальный контакт; заглушки вроде «не указан» отклоняются, и
модель получает ошибку с указанием переспросить клиента.

**Кнопка «Отправить мой номер».** Номер из Telegram подтверждён платформой —
надёжнее, чем то, что модель «увидела» в тексте.

**Последовательная обработка одного чата.** `asyncio.Lock` на `chat_id`:
три сообщения подряд не превращаются в три параллельных прохода и кашу в истории.

**Троттлинг включён по умолчанию.** Каждое сообщение — платный вызов LLM.
Без лимита один спамящий пользователь выжигает бюджет за вечер.

**Секрет вебхука проверяется всегда.** Заголовок `X-Telegram-Bot-Api-Secret-Token`
сверяется через `hmac.compare_digest` до любой другой работы и не зависит от
того, успел ли отработать `lifespan`. Без этого эндпойнт принимал бы поддельные
апдейты от кого угодно.

**Апдейты обрабатываются в фоне.** Вебхук отвечает `200` сразу: ответ LLM
занимает секунды, а Telegram на медленный ответ начинает слать ретраи того же
апдейта.

**Лид сохраняется до уведомления.** Упавшая отправка админу не теряет заявку —
она остаётся с `admin_notified = 0` и досылается при следующем старте.

**Деградация вместо тишины.** Если LLM недоступна после всех повторов, клиент
получает вежливое сообщение, а его реплика всё равно сохраняется в истории.
Тот же принцип у обработчика ошибок: любое необработанное исключение всё равно
заканчивается ответом клиенту. Молчащий бот — это ушедший клиент.

**Суточный лимит расходов.** Троттлинг ограничивает частоту, но не объём:
15 сообщений в минуту — это 21 600 платных вызовов в сутки с одного аккаунта.
`DAILY_LLM_CALLS_PER_USER` и `DAILY_LLM_CALLS_GLOBAL` ставят потолок; при его
достижении бот не замолкает, а предлагает оставить контакт кнопкой.

**Заявка из кнопки не зависит от LLM.** Если лимит исчерпан или модель лежит,
присланный кнопкой номер сохраняется напрямую, вместе с выжимкой из предыдущих
вопросов клиента. Человек, уже нажавший кнопку, — самый горячий лид из всех;
терять его из-за недоступности модели недопустимо.

**Срок хранения персональных данных.** История и заявки удаляются по истечении
`RETENTION_DAYS_*` фоновой задачей, `/forget` удаляет данные по требованию
пользователя. Значение `0` отключает удаление — это должно быть осознанным
решением, а не значением по умолчанию.

## Продакшен: вебхук

```dotenv
USE_WEBHOOK=True
WEBHOOK_BASE_URL=https://bot.example.com   # только https
WEBHOOK_PATH=/telegram/webhook
WEBHOOK_SECRET=<длинная случайная строка>  # пусто — выведется из BOT_TOKEN
```

Приложение само вызывает `setWebhook` на старте и снимает его при остановке.
Terminate TLS ставьте перед приложением (nginx / Caddy / балансировщик платформы).

```bash
docker compose up -d --build
docker compose logs -f bot
```

Локально для проверки вебхука хватит туннеля:
`ngrok http 8080` → полученный https в `WEBHOOK_BASE_URL`.

| Команда   | Кто может | Действие                                          |
|-----------|-----------|---------------------------------------------------|
| `/start`  | все       | приветствие, сброс контекста                      |
| `/reset`  | все       | очистить историю диалога                          |
| `/forget` | все       | удалить все свои данные (история и заявки)        |
| `/help`   | все       | подсказка                                         |
| `/stats`  | админы    | воронка: пользователи, диалоги, лиды, конверсия   |
| `/export` | админы    | выгрузка всех заявок в CSV                        |

## Смена LLM-провайдера

Меняются две переменные — код одинаков для всех OpenAI-совместимых API.

```dotenv
# OpenAI (дефолт)
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini

# OpenRouter — Claude 3.5 Haiku
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=anthropic/claude-3.5-haiku

# OpenRouter — что-нибудь подешевле
LLM_MODEL=google/gemini-flash-1.5
```

Требование к модели одно: поддержка tool calling. Без неё лиды не сохранятся.

## Тесты

```bash

```

Покрыты: нормализация контактов, история с бюджетом символов, дедуп лидов,

## Что осознанно не сделано в MVP

Честный список — чтобы вы решали, а не обнаруживали в бою.

- **SQLite, а не PostgreSQL.** До нескольких тысяч диалогов хватает с запасом.
  Горизонтальное масштабирование потребует смены на Postgres — слой `db/`
  изолирован ровно для этого.
- **Троттлинг в памяти.** При нескольких репликах лимиты считаются
  независимо. Нужен общий счётчик — Redis.
- **Нет CRM-интеграции.** Лид уходит в Telegram и SQLite. Точка расширения —
  `AdminNotifier.notify`: рядом с отправкой добавляется вызов API amoCRM /
  Bitrix24 / Google Sheets.
- **Нет распознавания голосовых.** Голосовые получают вежливый отказ;
  подключается через Whisper в `handlers/dialog.py`.
- **Дедуп по последним 10 цифрам номера.** Достаточно в рамках одного чата,
  но не различает номера разных стран с одинаковым хвостом.
