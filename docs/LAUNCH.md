# Запуск демо: от нуля до первого лида

Пошаговый список для человека, который получил репозиторий и хочет показать
бота клиенту сегодня. Каждый шаг проверяемый: если проверка не прошла,
следующий шаг делать бессмысленно.

Занимает ~20 минут, из них 15 — ожидание ответов от @BotFather.

---

## Что уже готово в репозитории

- [x] Диалог с LLM, история последних сообщений, квалификация через function calling
- [x] Сохранение лида в SQLite + мгновенное уведомление админу в Telegram
- [x] Кнопка «отправить номер» и запасной путь захвата лида, когда LLM недоступна
- [x] Дедупликация лидов, суточные лимиты расходов, ретеншен персональных данных
- [x] Три готовые ниши (`rent_car`, `real_estate`, `tours`) — см. [NICHES.md](NICHES.md)
- [x] Режим витрины: один бот предлагает клиенту выбрать нишу кнопками — см. [NICHES.md](NICHES.md)
- [x] Проверка готовности `python -m app.preflight`
- [x] Деплой: systemd-юнит, Dockerfile, docker-compose, бэкап базы
- [x] 218 тестов, CI на 3.11 и 3.12

## Что должны сделать вы

Всё ниже — ваши шаги, кодом это не закрывается.

---

## Шаг 1. Ротируйте ключи, если они проходили через чат

Пропустите, если создаёте бота с нуля прямо сейчас.

Токен бота даёт полный доступ к переписке с вашими клиентами, ключ LLM —
к вашему балансу. Если они где-то засветились (чат, скриншот, переписка
с подрядчиком), считайте их скомпрометированными.

- Telegram: [@BotFather](https://t.me/BotFather) → `/mybots` → бот → *API Token* → **Revoke current token**
- OpenRouter: [openrouter.ai/keys](https://openrouter.ai/keys) → удалить ключ, создать новый

**Проверка:** старый токен перестал работать, новый вписан в `.env`.

---

## Шаг 2. Заполните `.env`

```bash
cp .env.example .env
chmod 600 .env          # файл не должен читаться другими пользователями
```

Обязательный минимум — три строки:

| Переменная       | Где взять                                                    |
|------------------|--------------------------------------------------------------|
| `BOT_TOKEN`      | [@BotFather](https://t.me/BotFather) → `/newbot`               |
| `ADMIN_CHAT_IDS` | [@userinfobot](https://t.me/userinfobot) — пришлёт ваш числовой ID |
| `LLM_API_KEY`    | [openrouter.ai/keys](https://openrouter.ai/keys) или платформа OpenAI |

Для OpenRouter не забудьте `LLM_BASE_URL=https://openrouter.ai/api/v1`.

`.env` в `.gitignore` и в репозиторий не попадает — это проверяется:

```bash
git check-ignore -v .env    # должен вывести строку .gitignore
```

---

## Шаг 3. Нажмите `/start` своему боту

Самая частая причина «демо не работает»: Telegram **запрещает боту писать
первым** тому, кто с ним не начинал диалог. Лид сохранится в базу, но
уведомление вам не придёт — и выглядеть это будет как «бот сломался».

Откройте своего бота в Telegram и нажмите «Запустить». То же самое должен
сделать каждый, чей ID стоит в `ADMIN_CHAT_IDS`.

---

## Шаг 4. Установите зависимости и проверьте готовность

```bash
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m app.preflight
```

`preflight` — это не формальность: он дёргает живые API и ловит отказы,
которые иначе всплывут при первом клиенте.

```
  OK   Конфигурация       режим polling, админов: 1
  OK   База данных        data/bot.sqlite3
  OK   Профиль ниши       rent_car: Batumi Rent — аренда автомобилей, 4 вопроса
  OK   База знаний        content/niches/rent_car.md, 1753 символов
 WARN  Выгрузка лидов     LEAD_WEBHOOK_URL не задан — только Telegram
  OK   Telegram: токен    @your_bot (id=…)
  OK   Telegram: админ-чаты  1 из 1 доступен
  OK   LLM: доступ        openai/gpt-4o-mini отвечает
  OK   LLM: tool calling   модель вызывает save_qualified_lead
```

Код возврата `0` — можно запускать, `1` — нельзя.

`WARN` не блокирует запуск. `FAIL` — блокирует, и текст ошибки говорит, что чинить.

**Отдельно про «LLM: tool calling».** Модель без поддержки инструментов
выглядит полностью рабочей: она отвечает, поддерживает диалог, клиент доволен —
и не сохраняется ни один лид. Если эта строка `FAIL`, меняйте модель, а не промпт.

## Шаг 6. Прогоните сценарий и убедитесь, что лид дошёл

У каждой ниши есть готовый сценарий из реплик клиента:

```bash
.venv/bin/python -m app.profiles show rent_car
```

Отправьте боту эти реплики **по одному сообщению**, как писал бы живой человек.
На последнем шаге вам в Telegram должно прилететь уведомление:

```
🔥 НОВЫЙ ГОРЯЧИЙ ЛИД!
👤 Имя: Артём
📞 Контакт: +995 555 12 34 56
📅 Сроки/Даты: 12–19 октября
🚗 Запрос: кроссовер на автомате, подача в аэропорт
…
```

Проверьте, что лид лёг в базу:

```bash
# в Telegram, от имени админа:
/stats     # сколько диалогов, лидов и какая конверсия
/export    # CSV со всеми лидами
```

**Если уведомление не пришло, а бот отвечал** — почти всегда это шаг 3:
админ не нажимал `/start`. Логи покажут `TelegramForbiddenError`.

## Шаг 7. Подготовьте демо под конкретного клиента

1. Выберите нишу: `PROFILE=real_estate` (или `tours`, или свою — [NICHES.md](NICHES.md)).
2. Замените в базе знаний цены и условия на реальные — клиент узнаёт свой прайс,
   и разговор из «прикольная игрушка» превращается в «это про мой бизнес».
3. Поменяйте `COMPANY_NAME` и `COMPANY_CITY` на его данные.
4. Перезапустите бота и прогоните сценарий ещё раз перед встречей.

Переключение ниши — это перезапуск процесса, не правка кода.

## Что показывать на встрече

Порядок, который работает лучше всего:

1. **Дайте клиенту самому написать боту** со своего телефона. Не показывайте
   скриншоты — дайте потрогать.
2. Пусть спросит то, что реально спрашивают его клиенты. Бот отвечает по прайсу,
   который клиент только что узнал как свой.
3. Покажите **своё** уведомление о лиде, пришедшее за секунду.
4. Скажите цифру: бот отвечает круглосуточно за ~1 секунду, а средний ответ
   менеджера в мессенджере — десятки минут. Заявки теряются именно там.
5. Покажите `/stats` и `/export` — клиент видит, что это учёт, а не чат-игрушка.

Чего **не** обещать: бот не подтверждает наличие и не согласовывает скидки.
Это записано в базе знаний в разделе «Стоп-темы», и промпт это соблюдает.
Обещание «он всё сделает сам» ломает доверие на первой же заявке.

## Что осталось за рамками MVP

Осознанные пропуски, не забытые задачи:

- **Оплата и бронирование** — бот доводит до заявки, дальше работает человек.
- **Голосовые сообщения и фото** — не распознаются, бот просит написать текстом.
- **CRM-интеграции коробкой** — вместо них универсальный подписанный вебхук
  (`LEAD_WEBHOOK_URL`), который принимает Make, n8n, Zapier или свой бэкенд.
  См. «Выгрузка лидов» в [README](../README.md).
- **Мультиязычность интерфейса** — LLM отвечает на языке клиента, но кнопки
  и служебные сообщения на русском.
- **Админка** — вместо неё команды `/stats` и `/export`.

Всё это добавляется без переделки: слои разделены, лиды и диалоги уже в базе.
